Clan Manager

Automated Analytics & Promotion Dashboard

A fully automated management system for a 41-member competitive gaming clan — data pipeline, historical database, and interactive dashboard, with zero manual data entry.

The Problem

I lead a full 41-member clan in Clash of Clans. Deciding who to promote to Elder or Co-Leader — and who to remove for inactivity — requires knowing every member's war attacks, donations, and activity over months. Tracking that by hand is impossible, and gut-feel decisions caused drama. I wanted the decision to be data-driven and automatic.

What I Built

  • Automated data pipeline: Python scripts poll the official Clash of Clans REST API on a daily schedule, plus an automatic follow-up poll after each war ends so no war data is ever missed.
  • Historical database: every snapshot is stored in SQLite, building months of per-player history (war stars, donations, activity) that no game screen can show you.
  • Flask dashboard: a local web dashboard with the full roster ranked by rolling 90-day average stars per attack — so one bad war fades naturally instead of ruining a player's standing. It also shows donation averages, a daily-activeness percentage derived from 14 days of snapshots, war history, an ex-member archive, and per-player notes that persist even if a player leaves and rejoins.
  • Promotion engine: configurable requirements decide who qualifies for Elder or Co-Leader, and a YAML whitelist with per-player "protected" flags keeps trusted members safe from removal suggestions.

Engineering Details I'm Proud Of

  • Cross-device coordination: the system runs on both my Windows PC (Task Scheduler) and my Mac (cron), with the database syncing between them. A lock file with a 10-minute expiry prevents both machines from polling the API at the same time — a real distributed-systems problem solved with a simple, reliable mechanism.
  • Zero-maintenance philosophy: the whitelist regenerates automatically while preserving manual edits, and polling schedules itself around war end times.
  • Tested end-to-end: the project includes an API test suite covering the endpoints the pipeline depends on.
